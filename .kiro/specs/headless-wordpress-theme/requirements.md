# Документ требований

## Введение

Разработка headless WordPress темы для веб-студии, специализирующейся на создании сайтов и веб-приложений для малого и среднего бизнеса. Проект включает WordPress-бэкенд (REST API / WPGraphQL) и Next.js-фронтенд с SSR/SSG, поддержкой SEO и современными анимациями. Лендинг состоит из секций: Hero, О нас, Что мы делаем, Технологии, Портфолио (карусель), География работы, Контакты с картой. Весь контент всех секций управляется через панель администратора WordPress.

## Глоссарий

- **Frontend** — Next.js-приложение, отображаемое пользователю, с поддержкой SSR и SSG
- **Backend** — WordPress с активированной headless-темой и REST API / WPGraphQL
- **API** — REST API WordPress или WPGraphQL эндпоинт, предоставляющий данные фронтенду
- **Theme** — кастомная WordPress тема, не имеющая собственного визуального frontend-слоя, но предоставляющая данные через API
- **Admin** — панель администратора WordPress (WordPress Admin Dashboard)
- **HTTP_Client** — библиотека Axios, используемая на фронтенде для всех HTTP-запросов к API
- **Hero_Section** — первый экран лендинга с заголовком, подзаголовком и CTA-кнопкой
- **Portfolio_Carousel** — карусель с примерами выполненных проектов
- **Animator** — библиотека анимаций (GSAP или Framer Motion) на фронтенде
- **CTA** — call-to-action кнопка, призывающая к действию
- **SSR** — Server-Side Rendering, серверный рендеринг страниц в Next.js
- **SSG** — Static Site Generation, статическая генерация страниц в Next.js
- **ACF** — Advanced Custom Fields, плагин WordPress для управления кастомными полями

## Требования

### Требование 1: Headless WordPress тема

**User Story:** Как владелец студии, я хочу WordPress тему в headless-режиме, чтобы управлять всем контентом через привычную CMS, а фронтенд был отдельным Next.js-приложением.

#### Критерии приёмки

1. THE Theme SHALL отключать стандартный вывод WordPress и предоставлять данные исключительно через REST API и WPGraphQL
2. WHEN WordPress активирует Theme, THE Theme SHALL регистрировать кастомные типы записей: проекты (portfolio), технологии (technologies), команда (team), услуги (services), география (geography)
3. THE Theme SHALL регистрировать кастомные поля (ACF или нативные meta fields) для каждого типа записей, управляемые через Admin
4. WHEN запрос приходит на фронтенд-роут WordPress, THE Theme SHALL перенаправлять на Next.js-приложение
5. THE Theme SHALL включать файл `functions.php` с регистрацией всех хуков, эндпоинтов и типов записей
6. THE Admin SHALL предоставлять интерфейс для управления содержимым всех секций лендинга: Hero, О нас, Что мы делаем, Технологии, Портфолио, География, Контакты

---

### Требование 2: REST API и WPGraphQL эндпоинты

**User Story:** Как фронтенд-разработчик, я хочу получать все данные через единый API, чтобы Next.js-приложение могло отображать актуальный контент.

#### Критерии приёмки

1. THE API SHALL предоставлять эндпоинт `/wp-json/studio/v1/settings` с глобальными настройками сайта (название, логотип, контакты, SEO-метаданные), управляемыми через Admin
2. THE API SHALL предоставлять эндпоинт `/wp-json/studio/v1/hero` с данными Hero-секции (заголовок, подзаголовок, текст CTA-кнопки, фоновый медиа-элемент), управляемыми через Admin
3. THE API SHALL предоставлять эндпоинт `/wp-json/studio/v1/about` с данными секции «О нас» (история, миссия, ценности, числовые показатели), управляемыми через Admin
4. THE API SHALL предоставлять эндпоинт `/wp-json/studio/v1/services` с данными секции «Что мы делаем» (карточки услуг), управляемыми через Admin
5. THE API SHALL предоставлять эндпоинт `/wp-json/studio/v1/portfolio` с массивом проектов, включая изображения, описания и ссылки, управляемыми через Admin
6. THE API SHALL предоставлять эндпоинт `/wp-json/studio/v1/technologies` со списком технологий и их логотипами, управляемыми через Admin
7. THE API SHALL предоставлять эндпоинт `/wp-json/studio/v1/team` с данными о сотрудниках (фото, имя, должность), управляемыми через Admin
8. THE API SHALL предоставлять эндпоинт `/wp-json/studio/v1/geography` с данными о географии работы студии, управляемыми через Admin
9. WHEN клиент отправляет POST-запрос на `/wp-json/studio/v1/contact`, THE API SHALL сохранять заявку в базе данных и отправлять уведомление на email администратора
10. IF запрос содержит невалидные данные, THEN THE API SHALL возвращать HTTP 422 с описанием ошибки валидации
11. THE API SHALL поддерживать CORS для домена Next.js-приложения, настраиваемого через wp-config.php

---

### Требование 3: Next.js-приложение и структура фронтенда

**User Story:** Как посетитель сайта, я хочу видеть быстро загружающийся, SEO-оптимизированный сайт, чтобы найти студию через поиск и получить информацию без долгого ожидания.

#### Критерии приёмки

1. THE Frontend SHALL быть построен на Next.js 14+ с React 18+
2. THE Frontend SHALL использовать SSG для главной страницы лендинга с инкрементальной статической регенерацией (ISR) при обновлении контента в WordPress
3. THE Frontend SHALL использовать SSR для страниц, требующих актуальных данных в реальном времени
4. THE Frontend SHALL использовать HTTP_Client (Axios) для всех HTTP-запросов к API — нативный fetch не используется
5. THE Frontend SHALL загружать главную страницу (LCP) менее чем за 3 секунды на соединении 4G
6. THE Frontend SHALL реализовывать code splitting по маршрутам и секциям для оптимизации начальной загрузки
7. WHEN пользователь открывает сайт, THE Frontend SHALL отобразить все секции лендинга с данными, загруженными на этапе SSG/SSR
8. IF API недоступен во время запроса, THEN THE Frontend SHALL отображать статичный fallback-контент и сообщение об ошибке
9. THE Frontend SHALL быть полностью адаптивным для экранов от 320px до 2560px
10. THE Frontend SHALL реализовывать маршрутизацию через Next.js App Router или Pages Router

---

### Требование 4: SEO-оптимизация через Next.js

**User Story:** Как владелец студии, я хочу, чтобы сайт хорошо индексировался поисковыми системами, чтобы привлекать органический трафик.

#### Критерии приёмки

1. THE Frontend SHALL генерировать корректные мета-теги (title, description, Open Graph, Twitter Card) для каждой страницы на основе данных из API
2. THE Frontend SHALL генерировать файл `sitemap.xml` автоматически на основе страниц и проектов из WordPress
3. THE Frontend SHALL генерировать файл `robots.txt` с корректными директивами
4. THE Frontend SHALL обеспечивать серверный рендеринг HTML-контента для всех значимых секций, доступного для индексации поисковых роботов без выполнения JavaScript
5. THE Frontend SHALL использовать компонент `next/image` для оптимизации изображений с корректными атрибутами `alt` из API
6. THE Frontend SHALL предоставлять структурированные данные (JSON-LD) для главной страницы организации на основе данных из Admin

---

### Требование 5: Управление контентом через WordPress Admin

**User Story:** Как контент-менеджер студии, я хочу управлять всеми текстами, изображениями и данными сайта через панель WordPress, чтобы обновлять сайт без участия разработчика.

#### Критерии приёмки

1. THE Admin SHALL предоставлять отдельную страницу настроек темы для управления глобальными параметрами сайта (название, логотип, контакты, SEO)
2. THE Admin SHALL предоставлять интерфейс редактирования для каждой секции лендинга через ACF или кастомные мета-поля
3. WHEN контент-менеджер изменяет текст или изображение в Admin и сохраняет изменения, THE Frontend SHALL отображать обновлённый контент после следующей регенерации страницы (ISR или ручной revalidate)
4. THE Admin SHALL предоставлять возможность управлять порядком отображения карточек услуг, проектов и технологий через поле сортировки
5. THE Admin SHALL предоставлять возможность включать и отключать отображение отдельных секций лендинга без изменения кода
6. THE Theme SHALL реализовывать webhook или on-save хук, который инициирует ISR-регенерацию страниц Next.js при сохранении изменений в Admin

---

### Требование 6: HTTP-клиент Axios

**User Story:** Как фронтенд-разработчик, я хочу использовать Axios для всех API-запросов, чтобы иметь единообразную обработку запросов, ошибок и интерцепторов.

#### Критерии приёмки

1. THE HTTP_Client SHALL быть настроен как единственный HTTP-клиент в проекте — нативный `fetch` не используется для API-запросов
2. THE Frontend SHALL создавать экземпляр Axios с базовым URL WordPress API, настраиваемым через переменную окружения `NEXT_PUBLIC_API_URL`
3. THE HTTP_Client SHALL реализовывать интерцептор запросов для добавления необходимых заголовков (Content-Type, Authorization при необходимости)
4. THE HTTP_Client SHALL реализовывать интерцептор ответов для централизованной обработки ошибок API
5. IF сервер возвращает HTTP 5xx ошибку, THEN THE HTTP_Client SHALL выполнять повторный запрос не более 3 раз с экспоненциальной задержкой
6. THE HTTP_Client SHALL обеспечивать типизацию ответов API через TypeScript-интерфейсы

---

### Требование 7: Hero секция

**User Story:** Как посетитель сайта, я хочу видеть эффектный первый экран, чтобы сразу понять, чем занимается студия.

#### Критерии приёмки

1. THE Hero_Section SHALL отображать главный заголовок, подзаголовок и CTA-кнопку с данными из эндпоинта `/wp-json/studio/v1/hero`
2. WHEN страница загружается, THE Animator SHALL воспроизводить анимацию появления элементов Hero_Section с задержкой не более 300мс после рендеринга
3. THE Hero_Section SHALL содержать фоновый визуальный элемент (видео, градиент или параллакс-изображение), управляемый через Admin
4. WHEN пользователь нажимает CTA-кнопку, THE Hero_Section SHALL плавно прокручивать страницу до секции контактов
5. THE Hero_Section SHALL отображать корректно на мобильных устройствах (320px–767px), планшетах (768px–1023px) и десктопах (1024px+)

---

### Требование 8: Секция «О нас»

**User Story:** Как посетитель сайта, я хочу узнать о команде и ценностях студии, чтобы принять решение о сотрудничестве.

#### Критерии приёмки

1. THE Frontend SHALL отображать текстовый блок «О нас» с данными из эндпоинта `/wp-json/studio/v1/about` (история, миссия, ценности), управляемыми через Admin
2. THE Frontend SHALL отображать карточки сотрудников с фото, именем, должностью из эндпоинта `/wp-json/studio/v1/team`, управляемыми через Admin
3. WHEN секция «О нас» появляется в viewport, THE Animator SHALL запускать анимацию появления карточек сотрудников с последовательной задержкой 100мс между карточками
4. THE Frontend SHALL отображать числовые показатели студии (лет на рынке, проектов, клиентов) с анимацией счётчика при входе в viewport, данные управляются через Admin

---

### Требование 9: Секция «Что мы делаем»

**User Story:** Как потенциальный клиент, я хочу понять спектр услуг студии, чтобы оценить, подходит ли студия для моего проекта.

#### Критерии приёмки

1. THE Frontend SHALL отображать карточки услуг с иконкой, заголовком и описанием из эндпоинта `/wp-json/studio/v1/services`, управляемыми через Admin
2. WHEN пользователь наводит курсор на карточку услуги, THE Animator SHALL воспроизводить hover-анимацию карточки
3. THE Frontend SHALL отображать не менее 6 карточек услуг в адаптивной сетке (3 колонки на десктопе, 2 на планшете, 1 на мобильном)
4. THE Admin SHALL предоставлять интерфейс для добавления, редактирования, удаления и изменения порядка карточек услуг без изменения кода

---

### Требование 10: Секция «Технологии»

**User Story:** Как технический специалист клиента, я хочу видеть, с какими технологиями работает студия, чтобы оценить техническую совместимость.

#### Критерии приёмки

1. THE Frontend SHALL отображать логотипы и названия технологий из эндпоинта `/wp-json/studio/v1/technologies`, управляемыми через Admin
2. WHEN секция технологий появляется в viewport, THE Animator SHALL запускать анимацию появления логотипов
3. THE Frontend SHALL группировать технологии по категориям (Frontend, Backend, CMS, DevOps и др.), категории управляются через Admin
4. THE Admin SHALL предоставлять возможность добавлять, редактировать и удалять технологии и их категории без изменения кода

---

### Требование 11: Портфолио — карусель с проектами

**User Story:** Как потенциальный клиент, я хочу просмотреть примеры работ студии, чтобы оценить качество и стиль выполненных проектов.

#### Критерии приёмки

1. THE Portfolio_Carousel SHALL отображать проекты из эндпоинта `/wp-json/studio/v1/portfolio` в виде карусели, данные управляются через Admin
2. WHEN пользователь нажимает стрелки навигации карусели, THE Portfolio_Carousel SHALL переключать слайды с анимацией плавного перехода
3. THE Portfolio_Carousel SHALL поддерживать сенсорные свайп-жесты на мобильных устройствах
4. THE Portfolio_Carousel SHALL отображать для каждого проекта: скриншот, название, краткое описание, использованные технологии и ссылку — все поля управляются через Admin
5. WHEN пользователь нажимает на проект, THE Portfolio_Carousel SHALL открывать детальное модальное окно или переходить на страницу проекта
6. THE Portfolio_Carousel SHALL поддерживать автопрокрутку с интервалом 5 секунд, останавливаемую при взаимодействии пользователя

---

### Требование 12: Секция «География работы»

**User Story:** Как международный клиент, я хочу видеть, в каких странах работает студия, чтобы понять возможность сотрудничества.

#### Критерии приёмки

1. THE Frontend SHALL отображать визуальную карту или иллюстрацию с выделенными странами присутствия студии из эндпоинта `/wp-json/studio/v1/geography`
2. THE Frontend SHALL отображать список стран с количеством проектов или клиентов в каждой стране, данные управляются через Admin
3. WHEN пользователь наводит курсор на страну или кликает по ней, THE Frontend SHALL отображать всплывающую подсказку с информацией
4. THE Admin SHALL предоставлять интерфейс для управления списком стран и связанными данными без изменения кода

---

### Требование 13: Секция контактов и карта

**User Story:** Как заинтересованный клиент, я хочу легко связаться со студией, чтобы обсудить потенциальный проект.

#### Критерии приёмки

1. THE Frontend SHALL отображать контактную форму с полями: имя, email, телефон, описание проекта
2. WHEN пользователь заполняет и отправляет контактную форму, THE Frontend SHALL отправлять данные через HTTP_Client на эндпоинт `/wp-json/studio/v1/contact`
3. IF форма отправлена успешно, THEN THE Frontend SHALL отображать сообщение об успешной отправке и очищать форму
4. IF сервер возвращает ошибку валидации, THEN THE Frontend SHALL отображать сообщения об ошибках рядом с соответствующими полями
5. THE Frontend SHALL встраивать интерактивную карту (Google Maps или Leaflet.js) с маркером офиса студии
6. THE Frontend SHALL валидировать поля формы на стороне клиента перед отправкой: email по формату RFC 5322, телефон по шаблону E.164
7. THE Frontend SHALL отображать адрес, телефон, email и ссылки на социальные сети из эндпоинта `/wp-json/studio/v1/settings`, управляемых через Admin

---

### Требование 14: Анимации и UX

**User Story:** Как посетитель сайта, я хочу взаимодействовать с современным и красивым интерфейсом, чтобы получить положительное впечатление от студии.

#### Критерии приёмки

1. THE Animator SHALL реализовывать scroll-triggered анимации для всех секций лендинга с использованием GSAP ScrollTrigger или Framer Motion viewport
2. WHEN элемент входит в viewport, THE Animator SHALL воспроизводить анимацию появления длительностью не более 600мс
3. THE Frontend SHALL обеспечивать плавность анимаций не менее 60 fps на устройствах с GPU
4. WHERE пользователь предпочитает уменьшенное движение (prefers-reduced-motion: reduce), THE Animator SHALL отключать все несущественные анимации
5. THE Frontend SHALL реализовывать плавный скролл между секциями
6. THE Frontend SHALL отображать кастомный курсор или визуальный эффект на десктопных устройствах

---

### Требование 15: Демо-данные и документация

**User Story:** Как разработчик, устанавливающий тему, я хочу получить готовые демо-данные и документацию, чтобы быстро развернуть рабочее демо.

#### Критерии приёмки

1. THE Theme SHALL включать скрипт или плагин для импорта демо-данных (портфолио, команда, технологии, услуги, настройки всех секций)
2. THE Theme SHALL предоставлять файл `README.md` с инструкцией по установке, настройке и запуску WordPress-бэкенда и Next.js-фронтенда
3. THE Theme SHALL включать документацию по подключению темы к WordPress (шаги активации, настройка CORS, настройка API, настройка ISR webhook)
4. THE Theme SHALL включать файл `.env.example` для фронтенда с необходимыми переменными окружения, включая `NEXT_PUBLIC_API_URL` и ключи для ISR-регенерации
5. WHEN разработчик следует инструкции из README.md, THE Theme SHALL позволять запустить полнофункциональное демо за не более чем 30 минут
6. THE Theme SHALL содержать комментарии в коде на русском языке для ключевых компонентов и функций
